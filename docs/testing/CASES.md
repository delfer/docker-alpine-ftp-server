Точные mode sets, приоритет, тип ожидания, процедура и ссылки есть в [catalog.json](catalog.json). Общие fixtures, проверки и рецепты: [IMPLEMENTATION.md](IMPLEMENTATION.md). Для self все варианты из действий обязательны; это не произвольный выбор исполнителя.

Типы: contract — текущее обещанное поведение; known-defect — желаемая регрессия с обнаруженным нарушением; characterization — сначала зафиксировать фактическое поведение; hardening — желаемое усиление с возможным текущим отказом; decision — сначала выбрать контракт; future — после реализации функции.

P0 — критический PR набор, P1 — полная интеграция, P2 — расширенный/nightly/manual набор. P0 у known-defect не разрешает скрывать её широким xfail. Рецепт и тип ожидания определяют возможность запуска сейчас.
